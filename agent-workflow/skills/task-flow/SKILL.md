# Task flow

Перед работой в репозитории прочитайте `../../README.md`, `../../layers/core.md`, `../../layers/host-codex.md`, а также подходящие адаптеры окружения, технологий и проекта.

В проектном адаптере найдите путь к активному состоянию задачи и каталогу истории. Если активный checkpoint имеет `Status: Active` или `Status: Blocked`, сначала восстановите эту задачу: прочитайте checkpoint, проверьте `git status`, diff и файлы на диске, затем повторите необходимые целевые проверки. Не начинайте параллельную задачу и не доверяйте старому выводу команд без перепроверки.

Если активного checkpoint нет, создайте новый с уникальным `TASK-ID`. Если найден `Status: Closed`, сначала проверьте архив с именем `TASK-YYYYMMDD-NNN.md` в каталоге истории из проектного адаптера, сохраните закрытую запись при необходимости и только затем начните новый checkpoint с новым идентификатором. Повреждённое состояние или неизвестный статус считайте блокером и запросите решение.

При начале задачи создайте checkpoint по `../../templates/task-state.md`. Обновляйте его после Discovery, Clarification, каждого существенного блока Implementation, перед Manual QA, после исправления каждого бага, перед паузой или передачей работы и перед рискованным действием. Записывайте цель, критерии приёмки, границы, решения, изменённые файлы, проверки, режим проверки, блокеры и следующее действие; секреты не записывайте.

Следуйте жизненному циклу из слоя core. После discovery задавайте только сгруппированные существенные вопросы. Вносите минимальное безопасное изменение, предоставляйте инструкции для ручного QA и останавливайтесь до подтверждения пользователя перед audit и финальным review.

Перед остановкой на Manual QA установите в checkpoint `Phase: Manual QA`, укажите сценарий, ожидаемые результаты и `Next action: Wait for user manual QA`. Полученный от пользователя баг оставляйте в той же задаче, обновите checkpoint и вернитесь к точечной реализации, если scope не был явно расширен. При остановке или передаче другому агенту сохраните текущую фазу и все данные, необходимые для продолжения.

После подтверждения Manual QA установите `Phase: Audit` и обновите checkpoint до начала аудита. После аудита сохраните findings и результат проверки, установите `Phase: Code review`, затем после review запишите результат и установите `Phase: Close`. Перед заменой закрытого активного файла сохраните его в каталоге истории из проектного адаптера под именем `TASK-YYYYMMDD-NNN.md`.

При Close установите `Status: Closed`, `Phase: Close`, сохраните запись в каталоге истории под уникальным именем `TASK-YYYYMMDD-NNN.md` и не удаляйте историю.

Используйте технологический адаптер для команд и архитектуры. Используйте проектный адаптер для источников продукта, локальных правил и журналов. Не изобретайте второй workflow, не создавайте planning state другого инструмента и не выполняйте операции с branches, commits, merges или pull requests, если это явно не запрошено.
