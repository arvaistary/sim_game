# Чеклист аудита

Используйте после Manual QA. Отмечайте каждый пункт как `pass`, `fail`, `n/a` или `not run`, добавляя доказательства.

## Scope и поведение

- [ ] Scope и критерии приёмки сформулированы явно.
- [ ] Изменённое поведение соответствует требуемому результату.
- [ ] Non-goals и несвязанные изменения отделены.
- [ ] Edge cases и некорректный ввод покрыты.

## Корректность и данные

- [ ] Прослежены переходы состояния и общие callers.
- [ ] Persistence, serialization, retries и failure paths безопасны.
- [ ] Не добавлены пути потери данных, повреждения данных или устаревшего состояния.

## Безопасность и конфиденциальность

- [ ] Проверены trust boundaries, authentication, authorization, secrets и чувствительные данные, если применимо.
- [ ] Валидация ввода, кодирование вывода и раскрытие ошибок корректны.
- [ ] Целевой security adapter запущен, если доступен; иначе зафиксированы его отсутствие и локальный fallback.

## Пользовательское поведение

- [ ] Boot и основные действия работают.
- [ ] Переходы состояния и error states понятны.
- [ ] Проверены responsive, keyboard, pointer, accessibility и reduced-motion сценарии, если применимо.
- [ ] Скриншоты или другие конкретные доказательства подтверждают визуальные findings, если это необходимо.

## Сопровождаемость

- [ ] Существующие паттерны переиспользованы, где это уместно.
- [ ] Не добавлены ненужные абстракции, дублирование, dead code или зависимости.
- [ ] Документация и ссылки на проектные адаптеры актуальны.

## Проверки и записи

- [ ] Релевантные tests, lint, typecheck, build и static checks запущены либо осознанно пропущены с указанием причин.
- [ ] Baseline failures отделены от регрессий.
- [ ] Findings зафиксированы до исправлений.
- [ ] Статусы findings и пути проверки актуальны.
- [ ] Verification mode зафиксирован, если проверки затрагивал shell fallback.
