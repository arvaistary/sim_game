# План разработки (Roadmap)

**Актуализировано:** 27 августа 2026
**Стек:** Nuxt 4 + Vue 3 + TypeScript + Pinia + Nitro/Fastify API

## Правило приоритета

Работа делится на последовательные блоки:

1. **P0 — недостающие игровые системы.** Закрываем продуктовые пробелы, без которых жизнь персонажа не имеет полного цикла.
2. **P1 — доработка частично реализованных систем.** Доводим существующие механики до связного игрового состояния.
3. **P2 — частные случаи, UX и качество.** Исправляем отдельные сценарии после стабилизации систем.
4. **P3 — production и дистрибуция.** Выполняем после готовности основного игрового цикла.

Новые P2/P3-задачи не вытесняют P0/P1, кроме блокирующих дефектов и обязательных проверок безопасности данных.

## Текущее состояние

Уже есть:

- core loop, часовая модель времени и план дня;
- базовые навыки, XP-модель и ограничение ёмкости;
- образование и пролог MVP;
- базовые карьера, поиск работы, финансы, жильё, магазин и восстановление;
- событийный runtime: очередь, cooldown, границы дня/недели/месяца/года и возраста;
- календарь/планировщик периода — каркас первой итерации;
- GameWorld, application layer, SPA/server executors;
- PostgreSQL persistence implementation, CAS и idempotent commands; hosted smoke и rollback ещё не выполнены.

Подробные фактические статусы: [`IMPLEMENTATION_STATUS.md`](IMPLEMENTATION_STATUS.md). Операционные задачи: [`current backlog`](../new-plans/2026-08-20-current-backlog.md).

## Блок 1 — недостающие игровые системы (P0)

### 1.1 Смерть и концовки

**Статус:** базовый Game Over и каркас meta-progression есть; система не завершена.

- полный набор причин смерти и правил завершения жизни;
- финальный экран со статистикой;
- типы концовок и оценка жизни;
- экспорт результата;
- New Game+ после завершения жизни.

Зафиксированный runtime-default New Game+ (15% денег и два навыка на половине
уровня) является только тестовым baseline. В P1/P2 нужно пересмотреть его с упором
на реализм и без сильного преимущества от New Game+. Рассмотреть выбор места
рождения/происхождения или похожую систему стартовых условий, умеренно влияющую на
деньги, инвентарь и навыки новой жизни.

### 1.2 Социальные отношения

**Статус:** есть только базовая структура данных.

- отношения по шкале 0–100;
- социальные действия и их последствия;
- романтические отношения;
- поиск партнёра;
- друзья.

### 1.3 Семья и дети

**Зависимость:** после базовой системы отношений.

- брак и развод;
- рождение детей;
- состояние и возраст детей;
- воспитание и влияние семьи на жизнь персонажа.

### 1.4 Хобби и побочный заработок

**Статус:** структура хобби и UI есть; продуктового цикла нет.

- побочный заработок;
- мини-игры хобби;
- связь с временем, деньгами, навыками и событиями.

### 1.5 Достижения и трофеи

- система условий и фиксации достижений;
- экран достижений;
- бонусы и уведомления;
- локальный leaderboard.

### 1.6 Сезонные и праздничные события

**Зависимость:** модель событий из Блока 2.1; в этом блоке фиксируем scope и правила.

- календарь сезонов;
- праздничные события;
- влияние сезона на доступность действий, расходы, шкалы и события.

### 1.7 Транспорт и расширенная модель здоровья

- определить минимальный набор транспорта и его влияние на время/деньги;
- добавить состояния здоровья и последствия за пределами текущего Game Over по здоровью = 0;
- связать транспорт и здоровье с действиями, работой и событиями.

## Блок 2 — доработка частично реализованных систем (P1)

### 2.1 События

- довести контент до полного списка 25 событий GDD;
- добавить рабочие и возрастные события, включая childhood follow-up;
- подключить micro chance modifiers: risk/skill/state;
- расширить нейтральные, сюжетные и ветвящиеся последствия;
- добавить специальные события по профессиям.

Уже реализованы и не считаются отдельным незакрытым планом: очередь, cooldown, финансовые события и age hooks 30/40/50/60.

### 2.2 Финансы

- несколько инвестиционных продуктов;
- цели накопления;
- давление долгов и кредитов;
- экстренные финансовые события.

### 2.3 Жильё

- расширение уровней с визуальными улучшениями;
- долгосрочная аренда;
- изменение уровня жилья;
- влияние соседей на комфорт.

### 2.4 Работа, магазин и инвентарь

- связать покупки вещей с `playerState.possessions`;
- сделать компьютер требованием для интернет-поиска работы;
- завершить магазин: категории learning/things/home и реальный checkout;
- связать карьерный прогресс, инвентарь и специальные рабочие события.

### 2.5 Календарь и планировщик периода

Первая итерация:

- каталог на `/game/plan` с добавлением в любой день;
- мягкие предупреждения по прогнозу шкал;
- остановка прогона внутри дня при невыполнимом следующем шаге;
- `copyDay` и редактирование остатка;
- обработка очереди событий между днями.

Вторая итерация:

- освоение 7/21/40 дней;
- монотонность действий;
- локации и синергия маршрута;
- история и сводка периода;
- мобильная подача со свайпом и bottom sheet.

### 2.6 Глубина навыков

- разметить `learningMethod` в каталоге действий;
- устранить конфликт потолков 10/1000 и несогласованную шкалу прогресса;
- подключить нелинейную XP-модель к реальным действиям;
- добавить деградацию, синергии и capstones;
- после телеметрии выполнить балансировку.

### 2.7 Обратная связь жизненного цикла

- визуальное старение и этапы жизни;
- цели и мотивация;
- недельный и месячный отчёты.

## Блок 3 — частные случаи, UX и качество (P2)

### 3.1 Частные игровые сценарии

- unlock recruitment agency через gameplay;
- определить, нужен ли сброс сохранённых вакансий при смене недели;
- завершить E2E: поиск работы → пустой результат → недельный лимит → увольнение → quit;
- закрыть частные checkout/инвентарь/корзину и empty-state случаи;
- подключить microbeat/minigame в пролог;
- вручную проверить пять `compact`-прогонов, university flow, refresh/resume и adult-start.

### 3.2 Архитектурный и тестовый долг

- перевести stores в true projections;
- удалить deprecated `bridge.ts` и `legacy.ts` после стабилизации server-mode;
- добавить E2E-покрытие основных user flows;
- добавить Nitro/server-mode integration tests;
- добавить Storybook или dev showcase компонентов.

### 3.3 Design system и базовые настройки

- завершить Accent + Glass Foundation, Shell, shared UI и страницы;
- сократить raw colors и провести visual regression в темах/palettes;
- добавить звук/музыку;
- реализовать `SettingsPage.vue`.

## Блок 4 — production и дистрибуция (P3)

### 4.1 Server persistence rollout

- развернуть merged `main` через main-only Vercel workflow;
- проверить сохранность состояния, `/health`, `/ready`, retry и conflict smoke;
- провести rollback/recovery rehearsal;

### 4.2 Эксплуатация

- production build optimization;

### 4.3 Платформы

- Яндекс.Игры;

- PWA/offline-capable SPA build.

## Порядок выполнения

1. Блок 1: смерть/концовки, отношения, семья, хобби, достижения; зафиксировать scope сезонов.
2. Блок 2: события, финансы, жильё, работа/инвентарь, календарь, навыки; затем реализовать сезонные механики.
3. Блок 3: частные сценарии, архитектурный долг, UX и QA.
4. Блок 4: hosted persistence, эксплуатация и платформы.

Зависимости: отношения → семья; события → сезоны/достижения; навыки → календарь и баланс; готовый игровой цикл → production rollout.
