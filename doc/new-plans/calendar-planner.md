# Календарь и планировщик периода — краткое описание

**Полный документ:** [`doc/GDD/modules/15_calendar_planner.md`](../GDD/modules/15_calendar_planner.md)
**Статус:** творческий дизайн согласован, техническая реализация не спроектирована
**Дата:** август 2026

---

## Суть

Календарь — это способ подачи, а не новая механика. Механически это упрощённый планировщик: колонка на каждый открытый день, карточки действий внутри колонки, копирование карточек как основной жест. Сетки часов и привязки к времени суток нет.

Игрок раскладывает действия по дням, видит прогноз того, как это скажется на характеристиках, и проживает весь период одним подтверждением.

## Ключевые решения

| Решение | Формулировка |
|---------|--------------|
| **Горизонт** | Растёт с навыком «Тайм-менеджмент»: от 1 дня до 7 |
| **Прогноз** | Одна функция для проверки, отображения и выполнения. Детерминированная, случайные события в прогноз не входят |
| **Бюджет** | Жёсткий запрет только на деньги, часы и требования. По характеристикам — предупреждение с правом риска |
| **Дефицит** | Новое состояние с последствиями: раньше характеристики просто упирались в границу диапазона |
| **Освоение** | Серия повторов подряд с мягким угасанием: 7 дней — эффект, 21 день — расход ресурсов, 40 дней — минус час |
| **Монотонность** | Повтор внутри одного дня даёт убывающую отдачу. Однообразие в моменте наказывается, постоянство во времени награждается |
| **Синергия** | Метки локаций: соседние действия одной локации платят дорогу один раз. Именно это делает порядок карточек значимым |
| **Прерывание** | Пошаговый прогон. Событие само не останавливает — останавливает только его последствие, делающее остаток невыполнимым |
| **Остаток** | Сохраняется в календаре, редактируется, прогон продолжается одной кнопкой |
| **Интерфейс** | Компактная панель текущего дня на дашборде плюс полный календарь на отдельной странице. Мобильная версия — свайп по дням и добор действий из нижней панели |

## Что придётся привести в порядок попутно

- Свести часовой бюджет к одной модели: сейчас одиночное действие тратит часы недели, а планировщик считает часы суток.
- Добавить черновик плана в автосохранение: потерять расписанную неделю при перезагрузке недопустимо.
- Ввести явные последствия дефицита, без которых правило «нельзя выйти за бюджет» не имеет смысла.

## Следующий шаг

План реализации. Предполагаемый порядок: единая модель часов и функция прогноза, затем пошаговый исполнитель с прерыванием, затем канбан-интерфейс и мобильная подача.
