## 1. План XP-модели — выполнен в коде

Все 11 задач плана есть в working tree. Модуль `src/domain/balance/skills/` — единственный источник порогов (`MAX_SKILL_LEVEL = 10`, таблица до 10 000).

| Задача | Статус |
|--------|--------|
| 1. Потолок 10 | сделано — `skills-constants.ts` реэкспортирует константу |
| 2. Нелинейные пороги | сделано |
| 3. Множители способов | сделано, `work: 1` |
| 4. Расчёт опыта из часов | сделано |

| 6. `execute-action` на часах | сделано, `applySkillXp` + `distributeSkillXp` |
| 7. Store только проекция | сделано, `useSkills` удалён |
| 8. Карточка без ложных «+уровней» | сделано, `createSkillEffects` |
| 9. Миграция сейвов | сделано, подключена в `LocalStorageSaveRepository` |
| 10. Мёртвые модули | удалены `skill-system.*`, `skill-progression-config`, `skill-ui-explainability` |
| 11. Одна форма `SkillEntry` | `SkillLevels = Record<string, SkillEntry>` |

**Остаток именно XP-поставки, не глубины**

- В каталоге действий **нет ни одной метки `learningMethod`**. Все действия падают в `practice` (1.5). Мастер-класс кулинарии учит как домашний ужин, пока поле не разметить.
- Тексты `effect` в данных по-прежнему вида «Кулинарное мастерство +4». Карточка их не показывает, если есть `skillChanges`, но fallback и логи активности могут врать.
- Дипломы по-прежнему дают **уровни** через `applySkillChanges` — это было сознательным компромиссом плана.

Дальше по GDD 16 (не входило в XP-план): деградация, зона комфорта, синергии, капстоуны, эталон кулинарии, телеметрия калибровки.

## 2. Календарь — первая итерация есть, концепция закрыта частично

Появились: домен `src/domain/game-world/calendar/`, store `calendar-plan-store`, страница `/game/plan`, сводка на дашборде вместо полной панели дня.

### 2.1. Совпадает с концепцией

| Концепция | Где |
|-----------|-----|
| Горизонт 1–7 от `timeManagement` | `getCalendarHorizon` |
| Канбан: колонка на день, закрытые дни с уровнем открытия | `/game/plan` |
| Дублирование карточки, перенос между днями | store + страница |
| Прогноз той же логикой, что прогон, без случайностей | `forecastCalendarPlan` крутит копию мира через `planDayCommand` |
| Прогноз по дням с дельтой шкал | `StatBar` под колонкой |
| Кнопка «Прожить период» | `runPeriod` → `planDayAsync` по дням |
| Черновик в автосейве | `dayPlanner` и `calendarPlan` в `GAME_STORE_IDS` (BUG-DP-001 закрыт) |
| Единая проверка дневных часов | `executeActionCommand` режет `dayHoursRemaining` (BUG-DP-002 закрыт) |
| Частичный день без отката | NOTE-DP-002 принят, `success: false` + «День выполнен частично» |
| Дефицит блокирует старт дня | `getPlanBlockingReason`: энергия/здоровье 0, голод/стресс/настроение/форма на отображаемом −150 |
| Панель на дашборде + отдельная страница | `DayPlannerSummary` + `/game/plan` |

Концепцию дефицита в GDD 15.5 уже поправили под эту шкалу (−150 / внутренние 250).

### 2.2. Ещё не сделано

| Концепция | Что сейчас |
|-----------|------------|
| Добавление в любой день из каталога | `ActionCard` кладёт карточку в **день 0** общего `calendarPlan`. На странице календаря каталога нет |
| Копирование дня на другие дни | `copyDay` есть в store, в UI не вызывается |
| Порядок вверх/вниз внутри дня | Есть только drag на другой день |
| Жёсткий запрет vs мягкое предупреждение с правом риска | `validateCalendarAction` — жёсткий отказ, если прогноз дня неуспешен. Предупреждения 15/85 нет, alert только на 0/100 |
| Остановка **внутри дня** из-за дефицита после шага | Дефицит проверяется **перед** днём. Шаги дня всё равно прогоняются; неуспех действия не останавливает хвост, idle закрывает сутки |
| Событие останавливает только если ломает остаток | Прогон периода не смотрит очередь событий между днями |
| Остаток плана правится и продолжается | При неуспехе дня цикл рвётся; при успехе прожитый день вычищается (`advanceAfterDay`), закреплённые карточки переносятся |
| Освоение 7/21/40, монотонность, локации | Нет |
| Плёнка прогона, сводка периода, режим истории | Сообщение «Период прожит» / «остановлен на дне N» |
| Мобильный свайп и bottom sheet | Сетка колонок, не отдельный мобильный сценарий |
| Закрепление (`pin`) | Есть в коде, в GDD 15 этого жеста не было — расширение, не отклонение вниз |

Однодневная сводка, каталог действий и многодневный календарь используют первый день общего `calendarPlan`; после подтверждения план сдвигается на следующий день.
