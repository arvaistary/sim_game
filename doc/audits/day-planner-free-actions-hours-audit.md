# Аудит: лимит «3 свободных действия» → бюджет оставшихся часов

**Дата сессии:** 2026-08-09  
**Контекст:** ручное тестирование главного экрана; игрок видит «Свободные действия (0/3)», хотя действия уже имеют `hourCost` и день ограничен 24 ч.

---

## 1. Текущее поведение (as-is)

### 1.1. Двойное ограничение

План дня одновременно проверяет **два независимых лимита**:

| Лимит | Где | Сообщение / эффект |
|-------|-----|-------------------|
| **≤ 3 действия** | UI + composable + domain | «В плане уже три действия…», `Можно запланировать не более трёх действий` |
| **≤ оставшиеся часы суток** | composable `canConfirm` + domain `planDayCommand` | кнопка «Прожить день» disabled, `План превышает оставшееся время дня` |

Часы **уже считаются** (`plannedHours = sleep + work + Σ hourCost`), но слот «/3» в UI не отражает бюджет времени.

### 1.2. Точки в коде (лимит «3»)

```
src/composables/useDayPlanner/index.ts
  - canConfirm: plan.actionIds.length <= 3
  - addFreeAction: plan.actionIds.length >= 3 → return false

src/domain/game-world/commands/plan-day.ts
  - actionIds.length > 3 → reject

src/components/pages/dashboard/DayPlannerPanel/DayPlannerPanel.vue
  - заголовок: «Свободные действия ({{ plan.actionIds.length }}/3)»

src/components/game/ActionCard/ActionCard.vue
  - toast: «В плане уже три действия или действие недоступно»

test/unit/composables/useDayPlanner.test.ts
  - it('limits free actions to three…')

test/unit/domain/game-world/plan-day.test.ts
  - 4 actionIds → «Можно запланировать не более трёх действий»
```

### 1.3. Точки в коде (часы)

```
useDayPlanner:
  plannedActionHours = Σ action.hourCost
  plannedHours = sleepHours + workHours + plannedActionHours
  canConfirm: plannedHours <= time.dayHoursRemaining

planDayCommand:
  plannedHours > initialRemaining → reject
  idleHours = остаток дня → advanceHours('idle')
```

`dayHoursRemaining` приходит из `useTime` → `timeStore.dayHoursRemaining` (синхронизируется с `GameWorld` после `planDay`).

### 1.4. GDD

`doc/GDD/modules/01_general.md` и `03_core_mechanics.md` явно фиксируют **«до трёх свободных действий»** — расхождение с идеей «только часы» задокументировано в дизайне, не только в коде.

## 2. Проблема для игрока

### 2.1. Короткие действия «съедают слоты», а не часы

Пример (сон 7 ч + работа 8 ч → **9 ч** свободно):

- 3× прогулка по `1 ч` = **3 ч** из 9 → в плане **3/3**, ещё **6 ч** пустые, добавить нельзя.
- При лимите только по часам можно добавить до 9 одночасовых активностей.

### 2.2. Длинные действия упираются в «3», а не в часы

- Действие с `hourCost: 12` (есть в `social-actions.ts`) занимает 1 слот из 3, хотя по времени это почти весь свободный день.
- Игрок видит «1/3», хотя по смыслу важнее «12/9 ч» (и confirm уже должен быть disabled).

### 2.3. Добавление в план не смотрит на часы

`addFreeAction` проверяет только:

- тип действия (не sleep/work)
- `length >= 3`
- дубликат `actionId` в списке

**Не проверяет:** `plannedHours + action.hourCost <= dayHoursRemaining`.

Итог: можно набить 3 дорогих по времени действия → «Прожить день» disabled без явной подсказки *почему* (только общий warning внизу панели).

### 2.4. Дубликаты

Сейчас **нельзя** добавить одно и то же действие дважды (`actionIds.includes(actionId)`).

При часовой модели логично разрешить повтор («2× прогулка»), если хватает часов и денег. Это отдельное продуктовое решение.

## 3. Распределение `hourCost` (выборка)

Действия сильно различаются по длительности:

| Диапазон | Примеры |
|----------|---------|
| 0.5 ч | детские/социальные микро-активности |
| 1–4 ч | большинство развлечений, хобби |
| 6–12 ч | редкие «длинные» (напр. `hourCost: 12`) |

Лимит «3 слота» плохо коррелирует с реальным заполнением суток.

---

## 4. Целевое поведение (to-be) — гипотеза

**Единственный жёсткий лимит для свободных действий:** суммарные часы плана (сон + работа + действия) ≤ `dayHoursRemaining`.

### 4.1. UI

Заменить `(n/3)` на что-то вроде:

- `Свободные действия · 5 ч из 9 ч свободно` (где 9 = remaining − sleep − work), или
- `Запланировано действий: 5 ч / осталось 9 ч`

Показывать **оставшийся бюджет после сна и работы**, иначе игрок путает «24 ч» в шапке и фактический остаток под действия.

### 4.2. `addFreeAction`

Добавить проверку перед push:

```ts
const nextHours = plannedHours.value + action.hourCost
if (nextHours > time.dayHoursRemaining.value) return false
```

Опционально: toast «Недостаточно часов в плане дня».

### 4.3. Domain

Удалить блок в `planDayCommand`:

```ts
if (actionIds.length > 3) { … }
```

Валидация `plannedHours > initialRemaining` остаётся единственным gate на сервере.

### 4.4. GDD

Обновить `01_general.md`, `03_core_mechanics.md`: убрать «до трёх», описать лимит только через часы и нейтральный idle-остаток.

- **T0:** Пользователь указал на UI `(0/3)` при разных `hourCost` — гипотеза: лишний лимит слотов.

## 11. Полный UI-прогон книги и дневных лимитов — 2026-08-09

### 11.1. Старт и покупка

Создана новая игра через UI:

- взрослый старт, 18 лет;
- деньги: `5 000 ₽`;
- новый день: `0`;
- план дня: `24 ч`;
- свободные действия: `0 ч из 17 ч`.

Книга «Основы медитации» куплена за `690 ₽`; баланс после покупки — `4 310 ₽`.

В актуальной версии книга содержит **14 глав и 14 учебных часов**, а не 5 шагов. На карточке корректно отображаются `Глава N`, `Шаг N из 14` и остаток времени.

### 11.2. Первый игровой день

Учебная карточка читалась через UI: клик по карточке засчитывает главу, обратная сторона показывает текст главы. Пройдено 8 глав:

- прогресс: `Шаг 1 из 14 → Шаг 9 из 14`;
- остаток курса: `14 ч → 6 ч`;
- счётчик: `Учёба до сна 0/8 ч → 8/8 ч`;
- девятый учебный час не выполняется до сна.

После перехода на главный экран план дня показал:

- `Осталось часов: 23.5`;
- `Свободные действия · 0 ч из 16.5 ч`.

Таким образом, чтение не увеличило счётчик свободных действий, но в плане дня появился расход `0.5 ч`. Источник этого расхода в UI не объяснён.

### 11.3. Сон и второй игровой день

Выбран сон `7 ч`, затем выполнено `Прожить день`:

- день изменился `0 → 1`;
- неделя: `168 ч → 144 ч`;
- итог дня: `Потрачено 23.5 ч`, `нейтрально 16.5 ч`;
- план нового дня сбросился к `24 ч`;
- свободные действия сбросились к `0 ч из 17 ч`;
- лимит учёбы сбросился к `0/8 ч`.

Во второй день пройдены оставшиеся 6 глав. Книга завершена, показан результат `Обучение завершено`. После закрытия pop-up навыки начислены:

- `Медитация: 1 / 1000`;
- `Эмоциональный интеллект: 0.5 / 1000`.

### 11.4. Ответ на вопрос «сколько действий удастся выполнить?»

За полный путь выполнено **14 учебных действий**, по одному на каждую главу. Они распределились на два игровых дня: `8 + 6`.

Ограничение сработало не по бюджету свободных действий, а по отдельному учебному лимиту `8 ч до сна`. После сна оставшиеся 6 учебных часов выполнились в новом дне.

### 11.5. Укладываются ли учебные действия в дневной лимит?

Да, книга полностью укладывается в сутки при условии сна между учебными сессиями: первый день завершён через план `7 ч сна + 16.5 ч нейтрального времени`, второй день начат с чистым бюджетом `24 ч`.

При этом учебные действия **не отражаются в бюджете «Свободные действия»**: после завершения книги на главном экране остаётся `Свободные действия · 0 ч из 17 ч`. Это означает, что учебный лимит и бюджет свободных действий — разные механики.

### 11.6. Рабочее решение для текущей модели

Оставить два независимых ограничения, но явно разделить их в UI:

1. **Учёба:** максимум `8 ч до сна`; после сна счётчик сбрасывается. Для книги на 14 ч рабочий маршрут — `8 ч + сон + 6 ч`.
2. **Свободные действия:** отдельный дневной бюджет `17 ч`, который расходуют только действия, добавленные в план дня.
3. **План дня:** показывать источник любого расхода `0.5 ч`; сейчас после старта/чтения остаётся `23.5 ч`, но свободные действия показывают `0/16.5 ч`, что не объяснено пользователю. **Исправлено:** в планировщике строка `Потрачено сегодня: X ч` (источник — покупки и др. действия вне плана, напр. книга `hourCost: 0.5`).
4. На карточке книги явно показывать: `Глава N из 14`, `1 ч`, `Учёба до сна N/8 ч`. После восьмой главы — текст «Поспите для продолжения».

### 11.7. Итог аудита

Книга полностью прочитана за 14 действий и два дня; награды начислены корректно. Лимит учебных часов работает и не смешивается с лимитом свободных действий. Расход `0.5 ч` в плане дня — покупка книги в магазине (`hourCost: 0.5`), теперь отображается как «Потрачено сегодня».

### 11.8. Несоответствие бюджета на экране обучения

На экране обучения рядом с книгой отображается `Свободно на неделе: 168 ч` (после сна — `144 ч`). Для текущего сценария это неправильный ориентир: доступность следующей главы определяется дневным лимитом учёбы `8 ч до сна` и текущим остатком времени дня, а не недельным бюджетом.

#### Ожидаемое рабочее решение

Заменить недельный показатель на текущий дневной бюджет, например:

- `Учёба сегодня: 8/8 ч` или `Осталось учиться сегодня: 6 ч`;
- после сна счётчик сбрасывается;
- недельный бюджет оставить только на экранах, где он действительно влияет на доступность обучения.

Недельный и дневной бюджеты не смешивать в одной карточке: игрок должен сразу понимать, почему следующая глава недоступна сейчас.

**Статус:** реализовано — недельный показатель убран, добавлен «Осталось учиться до сна».

### 11.9. Сценарий: в дневном бюджете осталось 2 часа

Если текущий дневной бюджет учёбы равен `2 ч`, а одна глава требует `1 ч`, игрок должен получить возможность выполнить ровно две главы:

1. после первой главы: `Осталось сегодня 1 ч`;
2. после второй главы: `Осталось сегодня 0 ч`;
3. третья глава блокируется до перехода на следующий день/сна.

Если при этом лимит «учёба до сна» тоже равен `2/8 ч`, причина блокировки должна быть явно указана: `Дневной бюджет исчерпан`, а не «Поспите», если сон не является необходимым условием.

Важно различать:

- **дневной бюджет времени** — сколько часов осталось в текущем игровом дне;
- **лимит учёбы до сна** — сколько учебных часов можно выполнить до восстановления после сна;
- **бюджет свободных действий** — отдельный бюджет действий из планировщика.

Если на экране оставить только `Свободно на неделе: 2 ч`, игрок не поймёт, можно ли выполнить две главы сегодня, исчерпан ли лимит учёбы до сна или ограничен недельный ресурс. UI должен показывать все применимые ограничения раздельно и выводить конкретную причину блокировки.

**Статус:** реализовано — блокировка по лимиту до сна с текстом `Лимит учёбы до сна исчерпан (8/8 ч). Поспите, чтобы продолжить.`

### 11.10. Итоги завершённого дня должны открываться в модальном окне

После нажатия `Прожить день` под планом сейчас остаётся постоянный блок со статистикой завершённого дня: потраченные часы, нейтральное время, деньги и изменения характеристик.

#### Рабочее решение

Показывать итоги в модальном окне сразу после завершения дня:

- заголовок: `День завершён`;
- потрачено часов и нейтральное время;
- изменение денег;
- изменения характеристик и навыков;
- явная кнопка `Понятно`/`Продолжить`.

После закрытия модального окна оставлять план дня чистым и готовым к следующему дню. Постоянный блок под планом убрать, чтобы он не конкурировал с текущим бюджетом и действиями.
