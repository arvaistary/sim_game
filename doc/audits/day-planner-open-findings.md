# Открытые баги и замечания: план дня и обучение

**Актуализировано:** 2026-08-14
**Источник:** `doc/audits/day-planner-free-actions-hours-audit.md`  
**Назначение:** рабочий журнал только для неотработанных или не подтверждённых пунктов.

## Открытые баги

### BUG-DP-001 — черновик плана теряется после обновления страницы

**Статус:** исправлено 2026-08-14; `dayPlanner` и `calendarPlan` добавлены в автосохранение, store/repository round-trip покрыт тестами.

**Проверка 2026-08-10:**

1. В новой взрослой игре открыть «Действия».
2. Дважды добавить «Прогулка в парке» в план.
3. Перейти на «Дом» — обе записи отображаются, бюджет равен `4 ч из 17 ч`.
4. Обновить страницу — план сбрасывается до `0 ч из 17 ч`.

Межмаршрутное хранение исправлено; проблема осталась только при reload/restart.

**Причина в коде:** `day-planner-store` реализует `save/load` и включён в `gameStore.save/load`, но отсутствует в `GAME_STORE_IDS` плагина `src/plugins/auto-save.client.ts`. Изменение черновика не запускает debounced autosave.

**Критерии закрытия:**

- одно, несколько и повторяющиеся действия сохраняются после debounce и reload;
- сон и рабочие часы сохраняются вместе с действиями;
- после успешного `Прожить день` черновик сбрасывается и не восстанавливается после reload;
- есть тесты `store.save/load` и localStorage repository reload; отдельный browser-level debounce тест не требуется для domain-контракта.

### BUG-DP-002 — дневной остаток времени не ограничивает обучение и прямые действия

**Статус:** исправлено 2026-08-14; доменные команды проверяют дневной остаток перед действием, сменой и шагом обучения.

`executeActionCommand` и `simulateWorkShiftCommand` проверяют дневной и недельный остаток. Обучение проверяет `dayHoursRemaining` до шага и тратит один час через доменную модель времени.

Это расходится с общим правилом GDD: каждое действие должно укладываться в остаток текущих суток. Одновременно раздел обучения всё ещё говорит о недельном бюджете — правило требует согласования.

**Критерии закрытия:**

- при остатке дня `2 ч` доступны ровно две главы по `1 ч`;
- следующая глава блокируется текстом `Дневной бюджет исчерпан`;
- сообщение про сон показывается только при исчерпании лимита `8 ч до сна`;
- domain проверяет дневной остаток, UI лишь отображает точную причину;
- GDD однозначно фиксирует дневной или недельный gate для обучения.

### BUG-DP-003 — интеграционный flow планировщика падает до проверки результата

## Неотработанные замечания и решения

### NOTE-DP-001 — длинный список коротких действий

После снятия лимита `3` можно добавить до десятков действий по `0.5 ч`. В `DayPlannerPanel` нет soft-cap, collapse, `max-height` или внутреннего scroll. Нужен playtest и решение по UX; жёсткий доменный лимит без продуктового основания не добавлять.

### NOTE-DP-002 — план дня фактически не атомарный

`planDayCommand` выполняет шаги последовательно. Неуспешный шаг не откатывает уже применённые сон, работу, деньги или предыдущие действия; результат теперь явно помечается как частичный, а UI показывает отдельный статус.

Продуктовое решение принято: частичное выполнение официально закреплено:

- план выполняется последовательно без отката;
- неуспешные шаги явно попадают в результат и UI показывает частичный прогон;
- покрыто unit/integration-тестами.

### NOTE-DP-003 — запуск обучения требует двух подтверждений

После старта программы показывается result modal, затем игрок отдельно нажимает активную карточку `Нажмите, чтобы читать`. Это не функциональный баг, но остаётся UX-решением: оставить явное разделение «начать программу / читать» или сразу открывать первую главу.

## Подтверждённо закрыто и не переносится

- лимит `3` снят в domain/composable/UI и GDD;
- добавление ограничено доступными часами плана;
- повтор одного `actionId` разрешён, удаление выполняется по индексу;
- действия сохраняются между маршрутами;
- oneTime-книга не покупается повторно;
- `Потрачено сегодня` объясняет расход вне плана;
- лимит `8 ч до сна` и его остаток видны на карточке обучения;
- итоги дня показываются модальным окном;
- полный маршрут книги `8 + сон + 6` и награды подтверждены исходным аудитом.

## Проверка текущего UI

- на главной странице оставлен компактный итог дня вместо подробного редактора;
- подробный редактор доступен на `/game/plan`;
- рабочий пресет ограничен одной сменой текущего дня, недельный остаток `40 ч` не показывается как действие дня;
- варианты сна сопровождаются пояснением о восстановлении и доступном времени.
