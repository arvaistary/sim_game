# ADR-0002: Удаление ECS-архитектуры

**Дата:** апрель 2026
**Статус:** Принято

## Контекст

После миграции на Nuxt 4, проект содержал 21 ECS-систему (Entity-Component-System) + game-facade. Однако ECS создавал проблемы:
- Дублирование логики: stores + ECS делали одно и то же
- Сложность поддержки: два подхода вместо одного
- Размер бандла: 32 класса ECS = лишний код
- Технический долг: непонятно где искать баги

Команда понимала, что игра — это веб-приложение, а не ECS-игровой движок.

## Решение

Полностью удалить ECS-архитектуру:
- Удалить GameWorld (класс)
- Удалить 21 ECS систему
- Удалить game-facade
- Оставить только Pinia stores для state management

Оставить только доменный слой (`src/domain/balance/`) с:
- Игровыми действиями (~222 действия)
- Константами баланса
- Утилитами домена

## Последствия

### Положительные

- Простая архитектура: только stores и composables
- Меньше кода: удалены 32 класса ECS
- Ясный источник правды: Pinia stores
- Легче тестировать: не нужно мокать ECS World

### Отрицательные

- Потеря чистого разделения domain/presentation
- Stores могут содержать бизнес-логику (risk of bloated stores)
- Труднее изолировать domain для повторного использования

## Альтернативы

### Альтернатива 1: Сохранить ECS
- **Минусы:** Дублирование, сложность
- **Почему нет:** Устаревший подход для веб-приложения

### Альтернатива 2: Использовать ECS с другими stores
- **Минусы:** Слишком сложно для проекта
- **Почему нет:** Overengineering
